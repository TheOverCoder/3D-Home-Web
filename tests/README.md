# Tests

Two kinds: **unit tests** (Vitest, in Node: the rules, the saves and the models, in seconds) and the **end-to-end
suite** (Playwright: the game itself in a browser, about 25 minutes). `npm run check` runs the unit tests after the type
check and the linter; CI runs it beside the e2e shards.

## Unit tests

`npm test` (or `npm run test:watch`) runs `src/**/*.test.ts` in Node — no build, no browser, no WebGL
(`vitest.config.ts`; its `include` keeps the Playwright specs out). Next to the code they test:

## End-to-end tests

Playwright (Chromium, software WebGL) drives the production build through the `?debug` hooks
(`window.__home`: the zustand store, `playerState`, `teleport`, `look`, `camera`, `scene`, `gl`, `physics`, `view` (the drawing pass's switches and counters), `walk` (walking to a compass mark: start and stop one, how it ended, what it cost, a way found at once), `market` (the supermarket's interior casters, for `16`), `story` (a moment's film: its step, second and shot, `hold`, `skip`, `close`, `ask` to play it again, what each shot cost), `talk` (the lines the characters said, and the world a line would find now), and `fx`: the
effects' counts — bursts started and alive, coin flights, XP crystals — a clock to slow them for a screenshot, and `play` to start one).
Tests assert behaviour via the store and the player state, never exact copy, and pixels only twice: the bad-pixel test in `06` measures the share of pure-black pixels, because that bug was purely visual, and `24` the night's mean brightness (never black).

### Run

```bash
npm ci
npx playwright install chromium          # once (CI does this with --with-deps)
npm run test:e2e                         # builds, serves on :4185, runs everything sequentially
```

Offline / sandbox with a preinstalled browser:

```bash
PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npm run test:e2e
```

If something is already serving the build on port 4185 it is reused (outside CI). Software rendering is slow
(1-5 fps), so timeouts are generous; the whole run takes roughly 45 minutes (`05` alone: its three walks 10-20, ten times
the farm as long again). One worker, one browser: don't parallelise.

Thirteen tests start a page of their own (fresh boots on High and Medium, the lost context, the phone, the loader and its
second visit, the graphics lost while starting, ten times the farm in `05`, the measuring tool, the phone walking to a
compass mark in `19`, the farm opened again an hour later in `20`, the phone with a level claimed and opened again in
`22`, the farm closed an hour with the shop stocked in `23`, the daily gift's days in `35`) and take most of that time;
they are tagged `@boot`.
While iterating, `npm run test:e2e:quick` runs everything else (about 20 minutes).

Eleven tests are tagged `@full` as well: stable ones that boot a page of their own (High and Medium in `06`, the lost
context, the loader and the graphics lost while starting in `11`, the phone walking to a mark in `19`, the farm closed
an hour in `20`), the budget walk at ten times the farm in `05`, the counting check `26`, and in `16` the phone held
upright and the sun's map kept. `05` runs on the drawing-free WebGL
context (`nullgl.js`, `countingTest` in `helpers.ts`): the counts are three.js's own, on the CPU, and `26` checks them
against a real context view by view; the frames come at full speed, so its three walks take about a minute. A push runs the core
suite on GitHub without them (`ci.yml`, `--grep-invert @full`; `npm run test:e2e:core` locally) in eight shards side by
side, each given whole spec files by their measured time (`scripts/ci-shards.mjs` from `tests/e2e/times.json`, the
longest first, each to the shard with the least so far: about nine minutes each; `node scripts/ci-shards.mjs --plan 8`
shows them, and the `check` job fails when a spec has no time or a shard would pass 13 minutes); each shard prints its
files' seconds and any flaky test in its summary (`tests/e2e/fileTimes.ts`), the times to copy into `times.json`. A push
that changes only words (`.md` files: `update-v1/`'s notes, `plans/`) runs no CI. The `@full` tests run every night and by hand
(`full.yml`, Run workflow, with `--fail-on-flaky-tests`: a test that passes only on its retry turns the night red), and
a red night is the next thing to fix. Locally, run only the file of the area a change touches; `E2E_FRESH=1` never
reuses a server already answering on the port (a run killed half way can leave an old build's there).

One browser page is shared by the whole run (`helpers.ts`, the worker-scoped `game` fixture) because booting
the scene takes a minute or more. `game.ready(map)` resets the world before each test on a map (`src/scene/Maps.tsx`: the
house by default, in its living room where it always started; `'farm'` at a new farm's start — the map changed when
needed, the test farm owning the house; nothing open or carried, every pickup where it started, lamps on, door shut,
the farm's clock at noon and stopped: the light never changes between two frames compared; the daily gift put out of
the way and the week's events off, as `bootApp` puts them: the gift would open over a test by itself once a day, and the
events follow the device's date), so tests are independent in effect. The page's clock and its animations' timeline
stay in step there: Motion starts each animation on the clock (`performance.now`) and the browser plays it on the
timeline, so with the two apart every animation of the interface starts that much late (each sheet's way out waited as
long). Neither can be put back once moved (the game would see time go backwards; a timeline slowed through DevTools
never catches up), so a test that moves the clock (`20-away`) has a page of its own, `22-xp` slows each animation on its
own instead of the timeline, and `ready()` refuses a page whose two are more than 5 s apart. A new farm
(`farm.reset()`) starts on the farm: a test in the house puts it back there (`place: 'home'`, the house owned) in the
same call. The files run in order: `01-boot` boots the page (a new farm: on the farm).
A level reached by play pays its coins by itself (and brings a few building materials): a test that counts what an
action cost or paid reads the farm's `xp.paid` with the coins and leaves out what the levels reached since brought
(`levelPay` in `helpers.ts`; `levelPay` in `src/farm/testSaves.ts` for the unit tests), and a count of a building
material leaves out the levels' gifts (`gifts.came`): exact still, and never broken by a level its XP happens to reach.
A target the farm draws again or moves (an order's buttons, a compass mark) is pressed with `press()` (`helpers.ts`): a
real click, and the click sent to the element itself if it is replaced, moves or is covered at every try; a number that
runs on in real time is read in the same call as what shows it (the board's wait and its words, through `clock()`).
