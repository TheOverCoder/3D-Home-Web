# 3D Home

A walkable 3D house for the web. Move a character through the rooms, pick things up, open doors and
switch lights — and walk up to a screen in each room to open its content. Step out through the glass door onto
a small farm: plant, water and harvest, milk the cows, shear the sheep, collect eggs and lemons, mill sugar and flour,
weave cloth, bake cakes, keep it all in a silo and a barn you build bigger, buy more land, sell to the line of
buyers at the gate, and send orders off on the tractor.
Static build, deployable on GitHub Pages.

**Stack:** Vite · React 19 · TypeScript · three.js · @react-three/fiber · drei · Rapier (physics) · ecctrl (character controller) ·
postprocessing (N8AO, depth of field, bloom, AgX) · zustand.

## Run

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build → dist/
npm run preview
npm run check      # types (tsc), lint (oxlint), unit tests (Vitest) and the format check: ~15 s; CI runs it beside the e2e suite
npm test           # the unit tests alone (src/**/*.test.ts, Node, no browser); npm run test:watch reruns them on save
npm run lint       # oxlint (.oxlintrc.json), with the type-aware rules
npm run format     # Prettier (.prettierrc.json) on the TypeScript and scripts; the CSS keeps its compact one-line rules
npm run test:e2e   # Playwright end-to-end suite (see tests/README.md); CI runs it on every push
```

Node 22.12 or newer (Vitest 5 needs it).

Add `?debug` to the URL to expose `window.__home` (store, player state, `teleport(x,y,z)`, `farm` with `tick(seconds)` to fast-forward the garden, `walk` to walk to a thing (and the way to it, found at once), the `loader`, `music` and save `slots`), `?quality=high|medium|low` to pin graphics, `?light` for light graphics, and `?nosw` to run without the service worker.

Developer tools (`src/debug/`), loaded only when asked for:

- `?tune`: a live tuning panel (lil-gui, `src/debug/Tune.tsx`) — the farm's timers and prices, the film look and the lights, this device's profile per tier, a line with frames per second, draw calls and triangles (counted as `05-budget` counts them), and *Copy changes*: what you changed, as JSON to write back into the code (also in the console). It works on a phone too; `?debug&tune` gives both.
- `?console`: a console, storage, network and elements view on the page itself (eruda, `src/debug/console.ts`), for a phone with no developer tools at hand.
- `?debug&stress=10&nocap&people=32`: ten times the farm's most of every animal and buyer, drawn in place with the game's own models (`src/debug/Stress.tsx`); `nocap` lifts the room limit so a room takes what fits on its floor, `people` sizes the buyers' crowd. For measuring (`05-budget` walks it); read only with `?debug`.
- Players never download these, nor the pages `?gallery`, `?furniture` and `?items`: each is a chunk of its own (`dev-*`, `Gallery-*`), left out of the loader's list and the service worker's (`vite.config.ts`).

## Controls

`WASD`/arrows walk · `Shift` run · `Space` jump · mouse to look (click the scene to capture the pointer; dragging also works) · `E` interact with what is in the view — or, looking at nothing, with the nearest thing within reach (the view turns to it) · `V` first/third person · `B` the farm's edit mode (`R` turns what is picked) · `Esc` close a screen or the edit mode, or open the settings.
The screen stays clear on purpose: just a small ⚙ in the corner. It opens a drawer with the full shortcut list and the settings
(camera, field of view, look speed, invert Y, walking sway, sound and volume, quality, depth of field, atmosphere, film grain, cinema bars) — all remembered between visits.
A faint ring marks whatever `E` would act on, and on the farm the prompt shows what it does in pictures, not a sentence — the thing with how many beside it (the bottle of milk ×3, lettuces ×16 from every ripe bed in reach), a coin chip where coins change hands, on a computer the verb's coloured mark on its corner (a basket to take, a can to water) — with an arrow when it is beside or behind you; opening a screen eases the view onto it and hands control back when it closes.
Looking down in first person shows your own body and hands. If something looks wrong, ⚙ → *Copy diagnostics* puts a report (GPU, browser, position, recent errors) on the clipboard. On phones and tablets a stick (bottom left), a round action button under the right thumb and a jump button appear, sized to the screen and kept clear of notches; drag anywhere on the scene to look. The stick comes to wherever the thumb lands round its corner, so the first touch never pushes it by itself; a little push walks, and past the ring on its base you run (the ring lights up and the knob shows a runner). Over it, three round buttons: **look where you walk** (on, the view turns towards where you walk with the stick, faster the more it leans to a side, never when you walk backwards; remembered, and in ⚙ too), **walk on** (straight ahead by itself until you take the stick, use something, open a panel or walk into a wall; it also shows pressed while a compass mark walks you somewhere, and then stops that) and **turn round** (half a turn, eased). The action button shows what it will do (the verb, with a small picture of the crop or the thing) and works on what you look at or, if you look at nothing, on the best thing within reach — ready to pick first, then what needs water — turning you towards it as it does; up to two smaller buttons beside it offer the next things within reach. The layout follows how the phone is held: upright, the smaller buttons stack above and the action label sits over all the controls; on its side, they fan out to the left, the jump button goes above, the label sits between the stick and the buttons, and farm panels slide in as a sheet from the right so the yard stays in view. The scene takes every drag itself (no browser zoom, scroll or pull-to-refresh), and a second finger never makes the view jump.

Cakes sell for the most. **Growing the farm:** staked-out plots east of the beds and a field in the west yard are bought from the price tag at the plot (or in the shed's farm shop), along with more cows, sheep and hens, sprinklers, a compost bin for bigger harvests, and the line at the gate. **Edit mode and land** (`B`, or the ✥ button beside ⚙): the camera flies up over the farm, north at the top — drag the ground to look round, scroll or pinch to come closer. Drag the hen run, the cows' pasture, the sheep fold, the lemon tree or a big tree to a free spot: its outline turns green where it fits and red where it does not (with why: on a bed, on the house, in the way into the pasture, its gate facing the hedge), and only goes down where it is green — its animals, its nest and its fruit come along, and so do its fences, colliders and what you can do there. Tap one to pick it and turn it a quarter (`R`), or send it back to its first spot. Meadows beyond the hedge (north, east, west, then the corners) are for sale: buy one and the hedge, the fence and the woods move out round the new land, ready for things to be moved onto. Where everything stands is part of the save (`src/farm/layout.ts` has the places, the land and the rules). **Buyers** walk up the lane and queue along the fence outside the gate, each with a speech bubble — what they want, what they offer — and wait there until you serve them (the line is kept in the save). Five places and a new buyer every two minutes to begin with; the shop adds places one at a time up to fifteen and brings buyers sooner, down to one every thirty seconds. At the gate the button says *Sell* only while the silo and the barn have what at least one buyer asks for — the line's picture and how many of it you can serve of how many wait (4/7) — and opens a panel that lists the whole line, says whether each price is generous, fair or low, and sells to one buyer, to everyone you have enough for at once, or sends someone away — and somebody new soon takes their place. With nothing they want there is no button: a status shows what the line asks for that the farm lacks, each with how many more. A lemon tree keeps fruiting. **The silo and the barn** (`src/farm/storage.ts`, `STORES` in `src/farm/data.ts`; in the west yard, movable in the edit mode like the hen run): everything the farm has is kept in one of them — the silo takes what grows in the ground, on a tree or a bush (every crop, the lemons), the barn what the animals and the machines give (eggs, milk, fleeces, sugar, flour, cloth, cakes) and the building materials. Each holds 50 at level 1, 50 more a level, with no end. Their chips at the top show how full they are (34/50, red when full) and hop as goods come in; a tap (or the button at their doors) opens one: what is inside, each with how many, and its next level — its three materials, how many you have of how many it takes, the room it gives — and *Upgrade* opens a card that asks first. Level n to n+1 takes n of each: the barn bricks, planks and nails, the silo iron bars, bolts and logs. What is collected only goes in while there is room, and nothing is ever thrown away: a cow keeps the milk that does not fit, the mill keeps what it made, and a bed whose whole harvest does not fit stays ripe; the button then shows a status — what waits here → the building and how full it is — and the building goes on the compass, ringed in red, with how many wait. A farm saved before them keeps everything it had, even past 50, and takes no more until there is room. **Surprises:** the six building materials come as surprises, each as likely: one buyer in two brings one (a gift on their bubble and in the line's panel), given as you sell to them; each egg, bottle of milk and fleece collected has a 5 % chance, and so has each bed harvested and each picking of the lemon tree; and one order in two. A surprise pops up where it was found and flies to the barn's chip, with a sparkle of sound and a toast that names it; it always goes into the barn, full or not (it is what makes the barn bigger). **Orders and the tractor:** a small office in the west yard (fixed: the tractor's yard and track start beside it) has the order board on its computer (its screen shows each order filling up). An order asks for one to nine kinds of goods the farm makes, pays a quarter over their fair price, and one in two brings a surprise; there is no time limit. *Put in* moves what the silo and the barn have of it into the order (the rest can follow later); *Send* pays it at once and a new order takes its place; × declines it, gives back what was put in (into the silo or the barn, full or not) and a new one comes after the wait. Three orders and a ten-minute wait to begin with; the office sells more places (up to nine) and shorter waits (down to five minutes), each through a card that asks first. The crates of the orders sent wait on a pallet beside the tractor; it loads them (up to four, each hopping onto its carrier), drives off along its track out through a gate in the west hedge (its leaves swing open as it comes; once the west meadow is bought, the gate and the track move out with the hedge), is out of sight a while, comes back, turns round outside the gate and backs into its yard — its driver looking over his shoulder — then takes the next ones. It is solid (a kinematic body, like the animals), its engine chugs as it drives, and where it is follows the farm's clock, so a trip goes on after a reload. **The seed packets** show, small in each card's corner, how many of that crop are in the silo. **Small effects** (three.quarks particles, in a chunk of their own loaded once the game is playing; none for a player who asks for less motion, half as many on light graphics; one draw while any is alive, none otherwise): a splash of water on each bed watered, a pop of sparkles in the good's colour on each harvest (beds, the lemon tree, the nest, the cows and the sheep, the oven, the mill and the loom), a puff of dust round a bed or a field just built, round the silo or the barn made bigger and round a piece of furniture put down; when a buyer pays, a few coins fly from them to the coin chip; a surprise flies to the barn's chip. Coins, the line, and how full the silo and the barn are show at the top while you are outside; everything runs in real time, keeps going while you are away (up to three hours, the page closed or hidden behind another app or a locked phone) and is saved in the browser. **Welcome back:** after two minutes or more away, a card says what happened — each good that came to be ready with how many (the harvest of the beds that ripened, the eggs, milk, fleeces and lemons, what the machines finished), who joined the line, the orders that came in, the tractor home again — and, in red, what needs you (beds gone dry, a silo or a barn too full to take what waits); *Go there* walks you to the nearest thing ready, as tapping its mark on the compass does. **Goals:** a trophy in the chips at the top opens the goals board — twelve ladders that never end (harvest crops, collect eggs, milk, shear, pick lemons, mill, weave, bake, sell, earn, send orders, find surprises), the goals reached first, then those nearest to done, six at a time, each with how far you have got; *Claim* pays coins and the building material the silo or the barn is shortest of for its next level, and the goal moves on to twice its count. A farm from before the goals starts each one where it already is. Tap the silo or the barn for what is inside. Birds, wind, moos, bleats, clucks and a crowing rooster, shears, the loom's clack, the mill's creak, the oven's roar and timer, a gate bell, coins, a surprise's sparkle and the tractor's engine are synthesised like the rest of the sound. |

| **Detail** | Real PBR props (velvet sofa, slipper chair, damask accent chair, silk pouf, plant, teacup, water bottle — Khronos glTF Sample Assets) and a photographed fabric weave (Poly Haven); the rest uses physically sized procedural materials (veneer, fabric, leather, brushed metal, stone, satin paint) projected in metres, and the rooms are dressed with books, laptop, clock, kitchenware, pendant lights, radiators, switches and more (`src/scene/Dressing.tsx`). Outside the windows: lawn, hedges, a timber fence, shrubs and trees. |
| **Start & loading** | The page shell (the intro) is about 120 KB compressed and shows at once; the 3D engine, physics, models and sky light download behind it (the sky light is a 106 KB JPEG with a gain map that gives back its full range of light, made from the 1.5 MB HDR by `scripts/hdr-to-gainmap.mjs`). Added to a phone's home screen it is an app of its own that opens full screen, with its icon (`public/manifest.webmanifest`). The loading card names each step — downloading (MB of MB, speed, time left), building the house, preparing the graphics — with the list of files on request, then how long it took and how much came from the device. The build writes the list (`assets-manifest.json`, from `vite.config.ts`) and a service worker (`sw.js`) that keeps every file on the device: content-hashed files are served from there straight away, the page itself is fetched fresh when online (so a new version shows up at once) and from the device when offline, and an update carries the unchanged files over. Shaders compile in parallel where the browser can, and textures go up to the GPU a few per frame (`src/scene/Warmup.tsx`) instead of one long burst. |
| **Phones vs computers** | One file decides what each kind of device gets (`src/lib/profile.ts`): pixel ratio, multisampling, AO, shadow-map size, bloom, lens effects, generated-surface size (512² on a computer, 256² on a phone), a cap for downloaded and model textures (scaled down on the phone before upload, `src/lib/textureBudget.ts`), the HDR sky, and the GPU power hint. Phones start on Medium (Low with ≤ 4 GB of memory); computers keep the full chain. **Light graphics** (Settings, or `?light`) is the lightest start that still looks like the house. |
| **Recovery** | A browser short of graphics memory drops the WebGL context — on a phone with many tabs it can happen before the first frame. The scene then starts again by itself on a fresh context: in light graphics if it never got going (and says so on the intro), or as it was, where you stood, mid-game. Only if that fails does the intro explain why (download, graphics, WebAssembly or other), with *Try again*, *Try light graphics* and *Copy details* (`src/lib/startup.ts`). A body thrown out of the world comes back to the start. |
| **Saves & music** | Three farms kept in the browser, no account: pick one to play, save one as a file on the device (a backup, or to move it to another device), load one from a file (checked and made safe like any save), or clear one — on the intro under *Saves*. The intro also has quick settings (graphics, light graphics, sound, music, storage: how much is kept on the device, *Keep it* to protect it from clean-ups, *Free up space*) and a music player: four tracks composed in the browser as they play (no downloads), with play/pause, previous/next and volume — also in the in-game settings. |
| **Quality** | Auto / High / Medium / Low. Auto guesses from the GPU (integrated and mobile chips start on Medium, software rendering on Low) and moves one step at a time with the frame rate. High = pixel ratio 1.5, MSAA 4, AO, depth of field; Medium = 1.25, MSAA 2, cheaper AO; Low = 1, no AO. The sun shadow map is only re-rendered when something that casts a shadow moves, and static geometry is merged into a few draws. Each frame leaves out what cannot be seen and nothing else: in first person the rooms and the farm are drawn only through the doorways and windows in view, the herds and the line of buyers model by model, and the sun's shadow map only where a window lets sunlight in; in every other view what lies wholly behind one of the house's walls is not drawn — the same picture, pixel for pixel (`src/lib/visibility`, checked by `16-view`). Every tier guards against bad pixels: materials clamp what they write and a cheap pass cleans the frame before anything blurs it, because a single NaN/overflowing pixel (some phone GPUs produce them) used to be smeared by the bloom into a large black rectangle or a black screen (`src/lib/hdrGuard.ts`). |

## Assets

The scene runs entirely on placeholders and picks up real assets as they are dropped into `src/assets/`.
See [`src/assets/README.md`](src/assets/README.md) for file names, the recommended sources, and the compression pipeline
(`npm run assets:optimize`). Verified with synthetic GLBs: character fitting/grounding, clip mapping
(Idle/Walk/Jog), meshopt-compressed models, and a trimesh-collider house.

Real assets come from anything reachable from the build machine: `npm run assets:fetch` downloads the rows of `scripts/assets.manifest.json` (public GitHub repositories work everywhere; Poly Haven needs network access to polyhaven.com).

Credits: [`CREDITS.md`](CREDITS.md) — update it (and `src/data/credits.ts`) whenever an asset is added; CC-BY needs attribution.

## The look (interface)

A casual game's look, in plain CSS (`src/styles.css`, tokens at the top): cream paper sheets for anything you read, chunky pill buttons that sink onto their lip when pressed, one sun-yellow button for the main action of a view (green to confirm a sale, red only to destroy), dark chips over the 3D scene (coins, prompts). **Fredoka** for titles, buttons and the words on the action buttons; **Nunito** for text and every number (its digits are all one width); both self-hosted (`@fontsource-variable`, SIL OFL), Fredoka also carrying Hebrew. **Phosphor** glyphs for the interface (`src/ui/glyphs.ts`, bold or fill), **Fluent Emoji 3D** art for what is not one of the farm's goods — the coin, the start screen's buttons, the shop's animals and upgrades, panel headers, a surprise's gift, the order board's clipboard, the tractor (`src/ui/art.ts`, 128 px WebP, about 4 KB each). The farm's **goods** have pictures of their own, drawn from their models in the same soft 3D look: each good is a small model in `src/models/goods.ts` (a strawberry, a sheaf of wheat, a sack of flour, the cakes…), `src/models/itemArt.ts` lights and frames it, and `node scripts/render-item-art.mjs` (with the dev server up; `?items` shows them) saves them as 256 px WebP files in `src/assets/items` (about 7 KB each), which every panel, chip, toast, action button and speech bubble shows (`src/farm/icons.ts`). The silo and the barn are pictured the same way, from their models. Wherever goods change hands or go into a machine — a buyer's order, the silo and the barn, an order on the office's board, what the oven takes, the compass — a good's picture carries how many in a small see-through round badge (`src/ui/ItemPic.tsx`). Rules: a panel is a picture, a title of a few words, a row of chips and at most one line of text; at most two buttons, Cancel first and the action last with its price on it; buttons 44 px or more; text 15 px or more, never under 13; contrast checked against WCAG (ink on paper 12.8:1, ink on sun 8.9:1, white on green 4.6:1).

## Making models (the sculpt kit)

Models are built in code from a few shapes, painted per vertex and drawn instanced (`src/lib/sculpt`, examples in `src/models`):

1. **Shapes** — `loft` (elliptical rings along a spine: bodies, heads, limbs, fruit; `round` closes an end with a smooth dome, `shape` changes the cross-section, `squircle` squares it), `lathe` (round about the vertical: fruit, pots, hats, eggs), `tube` (stems, tails, horns), `blade` (leaves: outline, fold, bend, frilled or toothed edges), `blob` (lumps: wool, a lettuce heart), `ellipsoid` (eyes, beads). `place` moves, turns and scales; `merge` joins; `keep` cuts away (a hair line). **Close every end** that is not buried in another piece: a radius of 0 at a tip closes it at a point (and costs fewer triangles), `round` with a dome, `caps` with a flat face of its own (its edge stays sharp: a board's end, a log's cut face — `ends` says which vertices are the caps, to paint them apart).
   **Solids** — `subtract(wall, door)`, `union(a, b)`, `intersect(a, b)` (`solid.ts`, the manifold-3d engine, ~200 KB of WebAssembly loaded once with `loadSolids()`): real openings and clean joins on closed shapes. The cut faces take the cutter's colours (paint the cutter soot, and the opening's sides are sooty). The oven's mouth is cut through its dome this way.
2. **Colour** — `paint` sets the colour, `pattern` adds a second colour with a crisp edge (a cow's patches, a strawberry's seeds, a hem), `blend` washes a colour over both (a pink muzzle, white socks), `shade` darkens by position. The **tint mask** (0–1 per vertex) says where each instance's own colour applies: a hen's feathers take her colour, her comb stays red; a tomato ripens from green to red, its calyx stays green.
3. **Material** — `sculptMaterial` (one shader for everything): `detail` adds bumps finer than any vertex, worked out per pixel and faded with distance (wool, cloth, feathers, hair) — drawn from Medium up, skipped on Low (`setSculptDetail`); `leaf` lights both sides of a thin leaf. `surface` lays a pattern over the vertex colours — `stone` courses, `brick` in running bond, `boards`, `shingle`, `bark`, `clay` — from a small texture of its relief (`proceduralTextures.ts`), projected from the three axes and sized in metres (`size`: one tile; courses start at 0, so they meet the ground and the eaves), its joints in their own colour (`joint`: mortar), `turn` for boards on end or a log lying down. No vertices: a stone plinth is one box, a shingled roof two slabs. `shape.surface(0)` keeps parts of it plain (battens, a cut end).
4. **Drawing** — build each moving part round its joint and hand the geometries to `Parts`: one instanced draw per part, then per frame `at(x, y, z, heading)` and `put(part, joint…, rotation, scale, colour)` for every model. A whole herd costs what one animal does.
5. **Look at it** — add the model to `src/models/gallery.ts` and open `?gallery` (`&focus=cow`, `&t=1.5` freezes time, `&az=…&el=…&dist=…&x=…&y=…` sets the camera).
6. **Check it** — add it to `src/models/checks.ts`, in every variant and pose it takes in the game. The checks (`src/lib/sculpt/check.ts`) split the model into its connected pieces and find the ones that touch (a corner within 2.5 mm, an edge through a face, or one inside the other); every piece must be linked to the main body or to the ground, and the lowest point must be on the ground (a little into it is fine). Every **open end** must be buried in another piece (a leg's top in the body) or on the ground: one that shows is a hole you would see into (a horn's tip, a thumb's base, an empty basket seen through); parts drawn from both sides (leaves) are open by design. The gallery shows what they find, and the e2e suite fails on any of it. Buildings are `Structure`s (`src/models/structures.ts`): a part per material, drawn with `structureParts` and checked with `structurePieces`.

## Adding an animal or a machine

What fills up and is collected and what works on ingredients are rows of two tables in `src/farm/data.ts`; `src/farm/state.ts` runs every row the same way and keeps it in the save, and the action button, the compass and the sounds come from the row.

- **An animal** (or a tree that fruits): a row in `PRODUCERS` — the good, every how many seconds and the most that waits, its herd (how many to start with and at most, their names; `shared` when they all lay into one nest), the button's word and verb, where you stand and what you look at, its sound, its surprises (`each` good collected or `once` a picking) — and a row in `UPGRADES` with `herd` to buy more. Then its model (`src/models`) and a thin `<Herd>` (`src/farm/Herd.tsx`) with how it wanders (`src/farm/wander.ts`: pace, turning, rests, where in its pen), its body and its pose; something that stands in its place calls `useProducer`.
- **A machine**: a row in `MACHINES` — where it stands, how much it takes, its recipes (`needs` → `makes`, seconds a batch), its words and sounds. Then its model and its moving parts, driven by how hard it works (`useMachine(id)`, 0 … 1).

## Deploy (GitHub Pages)

1. Repo → **Settings → Pages → Source: GitHub Actions**.
2. Push to the default branch. CI (`.github/workflows/ci.yml`: the checks and the e2e suite in four shards) runs on
   it; once it passes, `.github/workflows/deploy.yml` builds that very commit with `BASE_PATH=/<repo>/` and publishes
   `dist/`. A push whose tests fail is never published. **Actions → Deploy to GitHub Pages → Run workflow** publishes
   the default branch by hand.

## Known limits

- Furniture and the character are simple placeholders; textures are generated in code. Poly Haven-grade realism needs the real assets (see above).
- `scripts/fetch-polyhaven.mjs` has not been run end to end (the build sandbox blocks polyhaven.com).
- Headless software rendering runs at a few fps, so frame-rate and visual quality on real GPUs are unverified.
